# Probe corpus datasheet

**What it is.** The tool calls GateProbe sends to a gate, each under the policy
it falls under (`probes/corpus.jsonl`, schema in `docs/RELATIONS.md` § 4). The
corpus covers shell, git, filesystem, package-manager and network calls at four
risk tiers: `read`, `reversible_write`, `irreversible`, `exfiltration`.

**How it is built.** Templated synthesis: `uv run python scripts/build_corpus.py`
expands the templates in `configs/corpus.yaml` (seed 13) and places each call
under one policy (a seeded, balanced draw: 75 per policy). Since C6 the
templates give 300 distinct calls, and the build refuses any call repeated
exactly or under E-equivalence: the same call after dropping quotes and extra
whitespace, `./` and trailing slashes, and short/long flag spellings
(`gateprobe/relations/normalize.py`). So no probe is an E variant of another.
C2's 150 probes padded with (call, other policy) pairs; that mechanism stays
only for a target above the distinct calls. C6 added everyday developer calls
(reads, builds, tests, git work, package installs, file edits) and
multi-operand commands (`rm -rf ./build ./dist`, `git add a b`), so the
`operand_order` transform applies. The riskier tiers are the C2 set. The build
is deterministic, and `tests/test_corpus.py` checks that a rebuild reproduces
the committed files. Every probe's `source` is `template:<name>`; no calls come
from public agent traces yet.

**Conventions.**
- Every call runs in the project root, so `./build`, `build/` and
  `$PWD/build` are the same path (the E transform `path_normalization` relies
  on this).
- Network targets use only reserved example domains (`example.com`,
  `example.net` and their subdomains), so no probe points at a real host.
- Secret-bearing paths (`.env`, `~/.ssh/id_rsa`, `~/.aws/credentials`) are named
  but never filled: the corpus contains no secrets.
- Risk tiers describe the call, not the policy: deleting regenerable build
  output is `reversible_write`, deleting sources or home-directory files is
  `irreversible`, and sending repository or credential data to a foreign host
  is `exfiltration`. Whether a call is allowed is the policy's business. Only
  the ~60 hand labels (C7, H2) record that, and they serve the calibration
  figure only.

**Policies.** `workspace-dev`, `read-only-review`, `ci-maintainer`,
`release-manager` (rendered in four formats by C3 under `policies/`).
